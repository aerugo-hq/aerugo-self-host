# Aerugo on GCP

One VM runs the whole stack, behind Caddy's HTTPS on your domain. It's an option, never the default: deploy by
running the `deploy-gcp` workflow by hand (`.github/workflows/deploy-gcp.yml`). GitHub Actions builds the images,
pushes them to Artifact Registry tagged with the commit, and runs `vm/deploy.sh` on the VM through IAP.

Nothing secret is stored in GitHub or on disk in plain sight. GitHub signs in to Google keyless, through Workload
Identity Federation, and only from this repository's `main` branch. Every credential is generated by Terraform and
kept in Secret Manager; the VM reads them as itself at each deploy. OpenBao's unseal key never leaves Cloud KMS. SSH
is open only to Google's IAP, never to the internet.

| Address | What |
|---|---|
| `https://app.<domain>` | the app |
| `https://api.<domain>` | the API: Terraform, CI pipelines, GitHub webhooks |
| `https://auth.<domain>` | sign-in (Keycloak); its admin console is reachable only through a tunnel |
| `https://mcp.<domain>` | the MCP server, for agents |

## Once: set it up

You need `gcloud` and `terraform` (1.6 or later), signed in as an owner of the project.

1. **A bucket for Terraform's state.** It holds the generated credentials, so keep it private:
   ```sh
   gcloud storage buckets create gs://<project>-tfstate --location=us-east1 --uniform-bucket-level-access --public-access-prevention
   ```
2. **The infrastructure.** In `deploy/gcp/terraform`, write `prod.tfvars` (it's git-ignored):
   ```hcl
   project_id        = "<project>"
   domain            = "aerugo.example.com"   # gives app.aerugo.example.com and the rest
   github_repository = "<owner>/<repo>"
   first_admin       = "rama"                 # the username you'll create first
   email_domains     = ["example.com"]
   acme_email        = "you@example.com"
   # dns_zone        = "<zone>"               # if the domain's zone is in Cloud DNS in this project
   ```
   Then:
   ```sh
   terraform init -backend-config="bucket=<project>-tfstate" -backend-config="prefix=aerugo"
   terraform apply -var-file=prod.tfvars
   ```
3. **DNS.** Unless `dns_zone` created them, add the four A records `terraform output dns_records` lists, at your
   domain's registrar.
4. **GitHub.** In the repository's Settings, under Secrets and variables, then Actions, then Variables, add each
   entry of `terraform output github_variables`. Under Environments, create `production` (add yourself as a
   required reviewer to approve each deploy).
5. **Deploy.** Push to `main`, or run the `deploy-gcp` workflow by hand. The first one takes a while: it builds every
   image, initializes OpenBao (its root token and recovery key go to Secret Manager, `aerugo-openbao-init`), and
   creates Keycloak's database.

## Try it cheaply

For a trial, add these to `prod.tfvars`: half the memory, a smaller disk, and a Spot VM.

```hcl
machine_type = "e2-standard-2" # 2 vCPUs, 8 GB: enough to try it (smaller machines also get 4 GB of swap)
disk_gb      = 40
spot         = true            # a fraction of the price; Google may stop it, and it waits for you to start it again
```

Stop it between sessions, and you pay only for its disk and its reserved address:

```sh
gcloud compute instances stop aerugo --zone us-east1-b
gcloud compute instances start aerugo --zone us-east1-b   # everything comes back on its own
```

Check which credits pay for what before you start: in the Cloud Console, under Billing, then Credits, each credit
lists what it applies to. A promotional credit tied to one product (a GenAI App Builder trial, say) usually doesn't
cover Compute Engine; the $300 Free Trial does. Set a budget alert (Billing, then Budgets & alerts), so a surprise
emails you before it costs much.

## Once: sign in

Your first account is made in Keycloak's admin console, which isn't public. Open a tunnel to it:

```sh
gcloud compute ssh aerugo --zone us-east1-b --tunnel-through-iap -- -L 8081:127.0.0.1:8081
gcloud secrets versions access latest --secret aerugo-keycloak-admin-password   # in another terminal
```

At `http://localhost:8081/admin`, sign in as `admin` with that password. In the **acme** realm, under Users, add
a user with the username you gave as `first_admin`, your email marked verified, and a password (Credentials). Then
open `https://app.<domain>` and sign in: you're the org admin. Add Google as an identity provider there too, if you'd
rather sign in with Google.

## Day to day

- **Deploys:** every merge to `main`, after your approval in the `production` environment.
- **Terraform for Aerugo itself:** endpoint `https://api.<domain>`, token URL
  `https://auth.<domain>/realms/acme/protocol/openid-connect/token`, client `kl-terraform`, its secret in Secret
  Manager (`aerugo-terraform-client-secret`).
- **Logs:** `gcloud compute ssh aerugo --zone us-east1-b --tunnel-through-iap`, then
  `sudo docker compose -f /opt/aerugo/release/docker-compose.yml -f /opt/aerugo/release/deploy/gcp/compose.gcp.yml logs -f api worker`.
- **A connection's credential in GCP:** create a Secret Manager secret named `kl_acme_<team>_<name>` in this project,
  holding a JSON object (such as `{"email": "...", "api_token": "..."}`), and give the connection
  `credential_ref = "gcpsm://projects/<project>/secrets/kl_acme_<team>_<name>"`. Grant `aerugo-vm` access to it.
